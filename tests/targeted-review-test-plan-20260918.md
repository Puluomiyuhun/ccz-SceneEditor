# 三项修补针对性 Review 测试方案

日期：2026-09-18  
对象：TXT 导出长文本、索引 Combo 的 Esc 恢复、道具保留编号边界

## 1. 测试目标与证据分层

本轮不把单一的源码正则命中当成完整验证，按下面四层收集证据：

1. **源码契约**：确认改动只落在预期路径，关键分支和边界条件仍存在，并且旧的危险实现已经消失。
2. **纯逻辑行为**：用不依赖 MFC 窗口的 C++ 回归用例验证编码、候选过滤、首个匹配、数字提交和边界编号。
3. **构建/交付一致性**：重新编译测试程序和 Release x86 编辑器，核对 staging 的 `s.exe` 与 Release 输出 SHA-256 一致。
4. **人工验收缺口**：列出只有真实 Win32 窗口或文件导出操作才能确认的项目，不把静态检查结果写成已实测。

## 2. TXT 导出长文本

### 契约

- `cczEditor2Doc.cpp::recur_export` 不得再使用 `char tmp[3000]` 或其他固定 3000 字节缓冲区。
- 先用 CP936 的 `WideCharToMultiByte` 查询包含结尾 NUL 的所需容量，再按容量分配动态缓冲区。
- 写文件时使用实际返回长度减一，不能把结尾 NUL 写入 TXT。
- 现有 `LongCharData` 的容量记录、替换和释放逻辑仍保持，不得被 TXT 导出修补删除。

### 行为用例

| ID | 输入 | 预期 |
|---|---|---|
| T1 | 3500 个可编码的中文字符（CP936 字节数超过 3000） | 转换成功，输出完整，不能被固定栈缓冲区截断或越界 |
| T2 | 空字符串 | 不写内容字节，只写树节点换行 |
| T3 | ASCII 与中文混合 | 输出字节数等于 CP936 实际返回值减一，文本内容不变 |
| T4 | CP936 不可表示字符 | 按 Windows 转换 API 的既有替换策略完成导出，不改变导出流程 |

T1--T4 的纯逻辑部分由编码回归程序覆盖；树遍历和真实文件选择框仍列入人工验收。

## 3. 索引 Combo 的 Esc 恢复

### 契约

- **无原生弹窗**时，索引 Combo 收到 Esc 必须恢复最近一次已提交文本和完整列表，并返回已处理；不能把 Esc 当作 Enter，也不能发送新的选择通知。
- **原生下拉弹窗已打开**时，仍由 `CBN_SELENDCANCEL` 恢复打开前快照；取消不得发送通知。
- **确认选择**时才发送一次通知；中间的 `CBN_SELCHANGE` 只更新高亮，不标记为已通知。
- 自动检索弹窗保留当前过滤结果；用户手动点击箭头时恢复完整旧列表，保留原来的浏览/滚轮行为。

### 状态矩阵

| 状态 | 操作 | 必须发生 | 禁止发生 |
|---|---|---|---|
| 已过滤、无弹窗 | Esc | 恢复完整列表、已提交文本 | `CommitIndexedInput`、`NotifySelectionChange` |
| 已打开原生弹窗 | Esc | 恢复打开前选择和文本 | 新选择通知 |
| 已打开原生弹窗 | 确定 | 提交候选并通知一次 | 重复通知 |
| 过滤结果弹窗 | 手动箭头 | 恢复完整列表 | 把过滤结果永久写回模型 |

另加一个需要在真实窗口确认的边界：索引 Combo 处于空闲状态（没有过滤词、没有原生弹窗）时按 Esc，产品契约应明确是“仍由 Combo 吞掉并保持当前值”，还是“放行给对话框执行取消”。当前实现选择前者；如果编辑器希望保留 Windows 对话框的 Esc 取消习惯，应把它列为待修 P2，而不能由静态脚本默认为两者都成立。

源码契约脚本检查分支结构；MFC 消息泵、焦点转发和真实滚轮行为需要在 staging 编辑器中人工验收。

## 4. 道具/人物数字边界

### 契约

- 道具完整列表和分段装备列表中，代码满足 `code % 256 == 255` 的保留项（至少 255、511）仍可通过原生列表选择，但不参与数字检索，也不能通过手动数字提交。
- 人物列表不套用道具保留规则；Data 号 255 和 1023 仍可检索、提交。
- 分段装备的显示全局编号与写回的本地 `selection_value` 必须保持分离。
- 非数字标签（如“无”）不应因为内部稳定值而误成为可提交的数字候选。

### 正反例

| 列表 | 编号 | 搜索 | 数字提交 |
|---|---:|---|---|
| 道具 | 254 | 允许 | 允许 |
| 道具 | 255、511 | 禁止 | 禁止 |
| 分段装备 | 255、511 | 禁止 | 禁止 |
| 人物 | 255、1023 | 允许 | 允许 |

纯 C++ 测试覆盖上述正反例、超长数字和首个匹配候选；GUI 仍需人工确认原生下拉列表中保留项可见且可点击。

## 5. 交付与回归门槛

自动门槛：

- 新增 `test_targeted_review_contract.ps1` 通过；
- 既有相关 PowerShell 回归脚本全部通过；
- `tests/*.exe` 全部退出码为 0；
- Release x86 MSBuild 退出码为 0；
- staging `s.exe` 与 Release 输出 SHA-256 相同，启动器和 INI 文件齐全。

人工门槛：

- 在 staging 中导出含超过 3000 个 CP936 字节的节点，检查文件完整性；
- 在无候选过滤状态按 Esc，确认文本/列表恢复且父窗口不误响应；
- 分别点击道具 255/511、人物 255，确认列表选择与手动输入契约没有混淆。

只有自动门槛和人工门槛都明确记录后，才能把本轮标记为“可放行”。
