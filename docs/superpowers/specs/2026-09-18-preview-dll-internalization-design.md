# 剧本编辑器预览 DLL 真正内化设计

日期：2026-09-18

状态：待用户审阅

目标仓库：`workspace/references/ccz-SceneEditor`

行为参照：`workspace/ccz_preview_ext`

## 1. 决策摘要

本项目采用“真正内化”路线：将 `cczPreviewExt.dll` 中仍有价值的纯逻辑和界面行为，经分析、删减与适配后编译进剧本编辑器；最终正式版本不再依赖 `cczPreviewExt.dll`、扩展启动器、远程注入、固定 EXE 哈希、固定 RVA 或运行时代码改写。

内化不是把 DLL 的全部源文件原样加入编辑器工程。迁移必须按职责重新划分：

1. 保留并整理纯逻辑核心；
2. 用编辑器源码中的直接数据访问替代窗口扫描和进程内快照；
3. 用原生调用替代固定地址 Hook；
4. 将界面改为编辑器拥有和管理的窗口；
5. 删除只为 DLL 注入、目标识别和异步桥接存在的代码。

迁移期间保留现有 DLL、启动器、当前 staging 和已验证 EXE，作为行为对照与回滚基线。只有内置版本通过完整验收后，才从正式发布目录移除 DLL 和启动器；历史基线仍保留在隔离目录中。

## 2. 背景与现状

现有增强系统由两套代码共同组成：

- 编辑器源码已经直接实现外场景读取、地图头像显示/移动/消失、场景位置写回、多选对齐与移动、可检索下拉框、文本换行辅助等功能；
- `cczPreviewExt.dll` 实现条件树、变量控制、台词预览、条件模拟、事件树重放和旧版编辑器桥接。

DLL 当初面对的是不可直接修改的成品宿主，因此采用以下手段：

- 校验宿主 EXE 的固定 SHA-256；
- 使用固定 RVA 定位预览函数和指令处理函数；
- 修改 `E8 rel32` 调用点；
- 枚举宿主窗口并读取 TreeView；
- 建立快照、定时刷新和跨窗口状态同步；
- 由外部启动器创建进程并远程加载 DLL。

现在编辑器源码已经可以稳定编译，这些桥接技术不再是必要条件。继续保留它们会让每次重新编译 EXE 都产生新的地址适配成本，也会形成编辑器状态与 DLL 推测状态并存的双重事实来源。

### 2.1 行为真值的优先级

旧 DLL 是回归参照，但不是可以不经检查直接照搬的唯一真值。迁移时按以下优先级裁决冲突：

1. 用户已经验收的实际交互和明确需求；
2. 当前稳定 staging 的可复现行为；
3. 剧本格式与编辑器源码中的结构化数据定义；
4. 已经验证过的自动测试；
5. 旧 DLL 的具体实现。

例如，0x79 整型变量测试的正式比较符集合是 `==`、`>=`、`<=`、`!=`。现有 DLL 源码中仍可看到只覆盖三种比较符且把第三种解释为严格小于的旧实现，这部分必须在迁移时按已确认语义修正，不能原样复制。

## 3. 目标

### 3.1 功能目标

内置版本必须保留当前 DLL 已验收的功能与交互：

- 台词预览，包括角色名、头像、改名指令、信息、旁白和地图文字；
- 条件树，包括布尔条件、整型条件、Choice/Case、分支状态和视觉状态；
- 0x79 整型条件完整支持 `==`、`>=`、`<=`、`!=`；
- Choice 在初次加载且没有显式选择时以 Case1 为默认激活项；
- 变量控制，包括布尔变量、整型变量、检索、赋值与恢复；
- 条件模拟对原生场景预览和台词预览的一致影响；
- 选择指令后推演到选定条的边界规则；
- 现有自动刷新、状态保持和文档切换行为；
- 与现有外场景、地图头像和原生预览增强协同工作。

### 3.2 架构目标

- 正式 EXE 不加载 `cczPreviewExt.dll`；
- 不保留目标 EXE 哈希和固定 RVA；
- 不修改自身代码页，不安装函数 Hook；
- 不通过窗口枚举猜测活动文档和事件树；
- 核心推演逻辑不依赖 MFC、HWND、HTREEITEM 或全局窗口状态；
- 当前文档、选中节点和预览状态只有一个权威来源；
- 每个模块可独立测试，界面层不承担脚本解析和重放规则；
- 功能失败时不破坏编辑器原生编辑、保存和预览能力。

### 3.3 非目标

本阶段不做以下工作：

- 不重新设计已经确认的窗口外观和交互文案；
- 不修改剧本文件格式；
- 不扩展新的条件指令或台词指令；
- 不顺带重写编辑器全部历史代码；
- 不把编辑器打包成绝对意义上的单文件程序；现有数据文件和配置文件仍按原有方式使用；
- 不在迁移过程中删除旧 DLL、启动器或历史 staging。

## 4. 方案比较与选择

### 4.1 选定方案：分层内化

建立独立的纯逻辑静态库，再由编辑器适配层向其提供明确数据。界面和生命周期由编辑器管理，Hook 与注入代码在迁移完成后删除。

优点：

- 能最大程度复用已有测试和已验证逻辑；
- 可以逐模块替换，任何阶段都能回退；
- 纯逻辑与 MFC 分离，未来动态预览可继续复用；
- 最终不存在 DLL 版本、宿主哈希和 RVA 同步问题。

代价：

- 需要建立新的编辑器适配层；
- UI 不能原样复制，需要重新明确所有权和生命周期；
- 迁移期会暂时存在旧 DLL 和新内置实现两套代码，但不会同时拥有写权限。

### 4.2 未选方案：整体编入后再清理

把 DLL 源文件直接加入 `cczEditor2.vcxproj` 可以较快生成一个内含旧代码的 EXE，但会继续携带窗口扫描、固定地址、后台线程和全局状态。它不能满足“更简洁的内置代码”目标，因此只允许在个别纯 Win32 绘制代码迁移时作为临时参考，不作为总体架构。

### 4.3 未选方案：完全重写

完全重写理论上可以得到最小代码，但会丢失当前条件树、变量控制和台词推演中大量边界规则。已有测试覆盖这些规则，重新推导没有收益且回归风险高，因此不采用。

## 5. 目标架构

目标实现分为四层。

### 5.1 `PreviewCore`：纯逻辑静态库

新增 `cczPreviewCore` 静态库项目，加入 `cczEditor2.sln`。核心公开头文件使用 C++17 类型，因此 `cczPreviewCore` 和引用它的 `cczEditor2` 均明确设置为 C++17、x86，并使用一致的静态 CRT。静态库最终链接进 EXE，不产生运行时 DLL 依赖。

该层包含：

- 指令目录和指令参数视图；
- 条件树解析；
- 布尔和整型条件求值；
- Choice/Case 状态；
- 模拟变量环境；
- Section 执行模型；
- 台词重放；
- 角色名、改名和头像解析；
- 台词覆盖层的显示模型；
- 变量列表和条件树的纯状态模型；
- 原生预览需要执行的逻辑计划。

该层禁止包含：

- MFC 类型；
- HWND、HTREEITEM 或窗口消息；
- 文件对话框和界面控件；
- 宿主 EXE 地址、RVA、汇编跳板；
- 后台轮询线程；
- 可变全局单例。

### 5.2 `EditorPreviewAdapter`：编辑器数据适配层

该层位于编辑器工程中，负责把当前编辑器对象转换为 `PreviewCore` 输入。它可以访问 `CTreeCtrl`、`HTREEITEM` 和 `ItemData`，但不负责条件判断、重放或绘制。

主要职责：

- 从明确传入的活动 View 和 TreeCtrl 读取当前文档；
- 从 `ItemData` 复制结构化指令数据；
- 根据文档路径、Section 路径和子节点路径生成稳定逻辑键；
- 生成完整的 `SectionInput` 和文档级变量索引输入；
- 校验节点深度、节点数量和 `ItemData` 完整性；
- 将核心生成的原生重放计划映射回当前 TreeView 节点；
- 在写回前重新确认节点身份，避免使用刷新前的句柄。

适配层每次刷新都生成按值拥有的数据。核心层不得缓存 TreeView 句柄或 `ItemData*`。

### 5.3 `PreviewSession`：会话与协调层

`PreviewSession` 是内置增强功能的唯一运行状态持有者，由场景预览窗拥有。它不创建后台工作线程，所有状态更新发生在编辑器 UI 线程。

它保存：

- 当前文档逻辑键；
- 当前 Section 逻辑键；
- 当前选中节点逻辑键；
- `ReplayOptions`；
- 模拟布尔变量和整型变量；
- Choice/Case 选择；
- 当前 `SectionExecutionModel`；
- 当前台词覆盖层模型；
- 文档级变量索引；
- 条件树展开状态和选中状态；
- 最近一次成功刷新结果与诊断信息。

会话规则：

- 同一文档内普通选中项变化保留模拟状态；
- Section 切换保留文档级变量值，按逻辑键保留可复用的分支选择；
- 文档切换清除前一文档的瞬态状态；
- 文档结构发生变化时，使用逻辑键保留仍然存在的状态，移除失效键；
- 不以 HWND、HTREEITEM 或内存地址作为长期身份；
- 刷新重入由会话入口统一保护，禁止在窗口或回调深处各自维护重入标志。

### 5.4 编辑器原生 UI 层

保留当前已经确认的界面行为，但改变其所有权：

- `CScenePreviewWnd` 继续负责场景图、角色、地图头像和台词覆盖层的最终绘制；
- 条件树窗口由 `CScenePreviewWnd` 或主框架显式拥有；
- 变量控制窗口由同一预览会话驱动；
- 条件树和变量窗口只提交类型化动作，不直接修改核心内部容器；
- 台词覆盖层直接绘制到预览窗的确定区域，不再创建跟随宿主窗口位置的透明覆盖子窗；
- 窗口关闭只改变可见性，不销毁预览会话状态；
- 编辑器退出时由正常的 MFC 对象析构顺序释放资源。

如果直接绘制到 `CScenePreviewWnd` 会改变现有 Z 序或裁剪表现，可以保留一个由编辑器自身拥有的子窗口；该子窗口仍属于 UI 层，不得恢复 DLL 式的宿主查找和位置轮询。

## 7. 数据流与刷新契约

### 7.1 选中节点变化

1. `CcczEditor2View` 明确通知 `CScenePreviewWnd` 当前 TreeCtrl、选中项和文档身份；
2. `EditorPreviewAdapter` 生成结构化 Section 输入；
3. `PreviewSession` 根据逻辑键同步已有模拟状态；
4. `PreviewCore` 构建执行模型；
5. 核心生成台词状态和原生预览重放计划；
6. 编辑器在当前 UI 线程应用计划；
7. 场景预览、台词覆盖层、条件树和变量控制使用同一份会话快照更新。

所有消费者必须读取一次刷新产生的同一代结果，不能各自重新解析事件树。

### 7.2 条件树和变量动作

1. UI 仅提交 `逻辑键 + 动作类型 + 类型化值`；
2. `PreviewSession` 原子更新 `ReplayOptions`；
3. 更新成功后触发一次完整刷新；
4. 更新失败时保持旧状态并返回诊断，不产生半写入状态；
5. 自动刷新与手动“激活子事件”走同一刷新入口。

### 7.3 原生预览边界

内置版继续采用当前已经确认的规则：预览推演到选定指令，包含选定条本身。核心负责生成应执行的节点序列，编辑器内部执行器负责清空场景状态并按序调用当前源码的指令处理逻辑。

不再通过 Hook 截获 `EvaluateToItem`；`CScenePreviewWnd::UpdatePreview` 是统一入口。现有外场景、地图头像和位置调整逻辑仍由 `CScenePreviewWnd` 执行，条件模拟只决定哪些节点进入重放计划。

### 7.4 自动刷新

自动刷新改为事件驱动：

- 选中节点变化；
- 指令编辑确认；
- 文档加载或关闭；
- TreeView 结构变化；
- 条件树动作；
- 变量控制动作；
- 当前 Mod 路径变化。

不使用鼠标移动、窗口轮询或定时扫描作为正常刷新来源。只有窗口布局自身需要的 MFC 重绘消息可以独立触发绘制，但不得重建执行模型。

## 8. 生命周期与所有权

- `CScenePreviewWnd` 拥有 `PreviewSession`；
- `PreviewSession` 按值拥有核心模型，不拥有 MFC 控件；
- 条件树和变量控制窗口持有对会话控制器的安全回调，不持有 `ItemData*`；
- 编辑器 View 负责通知选中项和结构变化，不把 TreeView 句柄交给后台线程；
- 头像、地图和精灵资源缓存继续由 `CScenePreviewWnd` 管理；
- 文档切换先使旧会话失效，再加载新文档数据；
- 编辑器退出时先关闭子窗口，再析构会话，最后由现有 `ExitInstance` 关闭 GDI+ 和 OLE；
- 不使用 DLL 固定、不等待桥接线程、不需要进程脱离分支。

## 9. 错误隔离

内置增强不得成为编辑器原生功能的单点故障。

- 适配层发现节点数据损坏时，放弃本次增强模型更新，并显示可诊断错误；
- 最近一次模型只在文档身份和结构代数仍匹配时短暂保留；
- 不能生成安全重放计划时，不应用部分节点；
- 条件或变量写入必须先在副本上验证，成功后整体提交；
- 台词头像、角色名或指令目录缺失时，只降级对应显示，不阻止原生场景预览；
- 增强刷新出现异常时，编辑器仍允许编辑、保存、关闭文档；
- Release 版本不弹出连续诊断框，诊断集中显示或写入受控日志。

## 11. 分阶段迁移

### 阶段 A：基线冻结与模块审计

工作：

- 记录当前 EXE、DLL、启动器和 staging 的哈希；
- 记录 DLL 测试和编辑器测试的实际通过数量；
- 完成逐文件“保留、适配、删除”清单；
- 建立功能验收矩阵和代表性剧本节点清单。

退出条件：现有版本可重复构建、可启动、测试结果已保存，回滚路径有效。

### 阶段 B：纯核心迁移

工作：

- 建立 `cczPreviewCore` 静态库；
- 迁移纯逻辑源码和测试；
- 清理不再需要的旧兼容 API；
- 保证核心不包含宿主窗口依赖。

退出条件：核心测试全部通过；编辑器可以链接静态库但尚不改变用户可见行为。

### 阶段 C：编辑器适配与影子验证

工作：

- 建立 `EditorPreviewAdapter` 和 `PreviewSession`；
- 从编辑器对象直接生成执行模型；
- 在不显示新 UI、不写回场景的影子模式下，与 DLL 基准结果比较。

退出条件：代表性剧本的 Section、条件、Choice/Case、变量索引和台词结果与基准一致。

影子模式只做读取和比较，不允许 DLL 与内置实现同时修改预览状态。

### 阶段 D：台词预览内化

工作：

- 将台词覆盖层接入 `CScenePreviewWnd`；
- 迁移头像和角色名解析；
- 验证自动刷新、改名和无角色文本指令。

退出条件：台词预览无需 DLL 即可完整工作，视觉与现有稳定版本一致。

### 阶段 E：条件树与变量控制内化

工作：

- 迁移条件树窗口和动作；
- 迁移变量控制窗口；
- 将两者统一接入 `PreviewSession`；
- 验证分支激活、恢复默认和整型变量赋值。

退出条件：所有条件和变量功能无需 DLL 即可工作，且不会产生双重状态。

### 阶段 F：原生预览重放内化

工作：

- 使用核心重放计划驱动 `CScenePreviewWnd`；
- 替代 DLL 的 `EvaluateToItem` Hook；
- 验证推演到选定条、条件分支、Choice 默认 Case1 和外场景相关功能。

退出条件：不加载 DLL 时，原生预览与所有增强功能完整协同。

### 阶段 G：清理与发布切换

工作：

- 从正式构建和 staging 移除 DLL 与启动器；
- 删除内置代码中的桥接兼容层；
- 执行完整回归、依赖检查和实际 UI 验收；
- 保留旧版本隔离归档和快速启动方式。

退出条件：正式 staging 仅使用内置增强 EXE，且功能矩阵全部通过。

## 12. 测试策略

### 12.1 核心单元测试

迁移现有 DLL 测试，覆盖：

- 条件树结构和分支可达性；
- 布尔变量与整型变量命名空间隔离；
- 0x79 的 `==`、`>=`、`<=`、`!=` 编码、求值和反向赋值；
- Choice/Case 选择；
- 台词重放边界；
- 改名覆盖规则；
- 头像档案解析；
- 变量索引；
- 逻辑键稳定性；
- 刷新去重和模型相等性。

与 launcher、目标哈希、RVA 和 Hook 有关的测试不迁移到新核心；它们只留在旧 DLL 回归套件中。

### 12.2 适配层测试

新增测试覆盖：

- `ItemData` 到结构化命令的复制；
- 文档、Section 和节点逻辑键；
- TreeView 重建后逻辑状态恢复；
- 损坏、缺失和超深节点的原子失败；
- 句柄刷新后的写回校验；
- 文档切换时状态隔离。

### 12.3 差分测试

对固定剧本和固定选中节点记录：

- 执行模型；
- 活动分支；
- 模拟变量值；
- 当前台词、角色名和头像编号；
- 原生重放计划中的指令逻辑键。

旧 DLL 和内置核心分别输出规范化结果，忽略 HWND、HTREEITEM 和内存地址，只比较逻辑内容。

### 12.4 编辑器集成测试

覆盖：

- 打开、切换和关闭多个剧本；
- 选中普通指令、条件、Else、Case 和嵌套子事件；
- 编辑指令后自动刷新；
- 激活分支和修改变量；
- 台词、内场景、外场景和地图头像共同显示；
- 条件窗口反复打开关闭；
- 保存和重新打开剧本；
- 无 DLL、无启动器情况下直接启动 EXE。

### 12.5 发布门禁

正式切换前必须满足：

- 编辑器与新核心全部自动测试通过；
- 旧 DLL 行为基准的有效差分项全部解释并获批准；
- Release x86 构建成功；
- 正式 EXE 不引用 `cczPreviewExt.dll` 导出；
- 正式目录缺少 DLL 和启动器时仍可正常启动；
- 代表性 R 剧本完成手动验收；
- staging 已更新并提供快速启动入口；
- 旧版本仍可从隔离归档启动。

## 13. 回滚策略

- 每个迁移阶段单独形成可构建检查点；
- 当前稳定 EXE、DLL、启动器和 staging 只读保留；
- 新内置功能在阶段 D 至 F 期间使用编译期开关隔离，默认只启用已经通过当前阶段验收的部分；
- 回滚时切换到上一阶段 EXE，不对剧本和数据文件执行逆向转换；
- 正式切换后仍保留旧版本归档，但不再把 DLL 放进新版发布目录。

编译期开关只用于迁移期，不成为长期的双实现配置。阶段 G 完成后删除旧路径和开关。

## 14. 验收标准

本项目完成必须同时满足：

1. 用户可直接启动新版编辑器，无需扩展启动器；
2. 新版编辑器不依赖 `cczPreviewExt.dll`；
3. DLL 中已验收功能全部可用；
4. 原生预览增强功能没有回归；
5. 条件树、变量控制、台词预览和场景预览共享同一份状态；
6. 源码中不存在目标 EXE 固定 RVA、自修改 Hook 和宿主窗口扫描；
7. 纯逻辑核心可以脱离 MFC 运行测试；
8. 正式构建、自动测试、差分测试和实际 UI 验收全部通过；
9. staging 和快速启动入口已更新；
10. 旧 DLL 版仍保留为隔离的可回滚历史基线。

## 15. 已确认的设计约束

- 最终选择真正内化，不采用 EXE 自动加载 DLL 作为正式架构；
- 内化需要合理增删调整，禁止粗暴复制全部 DLL 代码；
- 时间允许优先保证分析、结构和完整性；
- 迁移期间必须保留 DLL 和启动器用于回滚与行为对照；
- 最终版本完全摆脱外置 DLL 依赖；
- 每一阶段都必须有独立验证和可回退结果。
