# S 战场单位出场参数控制与地图可视化预览方案

**状态：已实施，等待真实 MFC 窗口与原生保存重开验收。**

## 目标

为 S 战场预览补齐三类出场指令的完整参数编辑：一套面向“今后新增单位”的默认参数，一套面向“当前已上场单位”的参数调整，并能直接在战场地图上查看当前布阵的参数。全场预览以地图上的单位、标记和目标关系为主体，不再使用全场参数表。所有值仍按当前 S 剧本、条件分支和部署类别隔离；不会把战场编号、Data 号、4B 槽号和形象索引混为一谈。

## 已核对的代码与证据

- [`battle_field_spec.cpp`](../../../cczPreviewCore/src/battle_field_spec.cpp) 和 [`battle_preview.h`](../../../cczPreviewCore/include/ccz/preview/battle_preview.h) 给出了三条 EEX 指令的字段角色与缓存字段。
- [`BattleEditorOps.h`](../../../cczEditor2/PreviewIntegration/BattleEditorOps.h) 已有 `BattlePlacementDefaults` 与 `BattleUnitPatch`；[`BattleEditorOps.cpp`](../../../cczEditor2/PreviewIntegration/BattleEditorOps.cpp) 已按字段角色创建新单位、应用补丁并标记 dirty 字段。单选参数编辑的核心数据能力大部分已存在，主要缺少完整默认值管理、编辑器控件和地图参数叠加层。
- [`cczEditor2View.cpp`](../../../cczEditor2/cczEditor2View.cpp) 的 `Dialog_70` 对应 0x46/0x47；其中 `id=data->id-70` 将友/敌配置分支分开，读写记录字段顺序与 `code_instruct` 对应。[`cczEditor2.rc`](../../../cczEditor2/cczEditor2.rc) 的 `IDD_DIALOG70` 显示武将、援军、隐藏、坐标、朝向、等级、兵种级别、AI，以及依 AI 模式显示的目标武将或目标坐标。`Dialog_75` 对应 0x4B，只配置编号、坐标、朝向、隐藏。
- R 预览已使用 [`portrait_resolver.h`](../../../cczPreviewCore/include/ccz/preview/portrait_resolver.h) / [`portrait_resolver.cpp`](../../../cczPreviewCore/src/portrait_resolver.cpp) 按 Data 号解析 Data.e5 头像字段，再从 Face.e5 头像档案取图；[`PreviewSession.cpp`](../../../cczEditor2/PreviewIntegration/PreviewSession.cpp) 通过 `populate_portrait_overlay` 使用这套解析。S 画布现有 [`BattlePreviewPage.cpp`](../../../cczEditor2/BattlePreviewPage.cpp) 已有逻辑格悬停、单位命中测试和双缓冲绘制入口，可承载单位信息浮层。
- 普罗工具不是随附可读 C# 源码；本地材料是编译后的 `Assembly-CSharp.dll` 和静态 IL 追踪记录 [`REVERSE-普罗工具战场布置器.md`](../../../../../REVERSE-普罗工具战场布置器.md)。静态 IL 分析记录了角色选择/鼠标预览、单体创建，以及 `mouse_painter` 的隐藏、方向、等级、类型、目标等批量刷写模式；这些刷写是编辑行为，与本方案的只读预览开关分开。用户截图直接证明普罗界面存在地图上的“行动方针”可视化示例；截图用于确定交互方向，不据此推断未被截图展示的内部实现。

## 三类指令的实际参数边界

| 指令 | 可持久化字段 | 编辑器表现 |
|---|---|---|
| `0x46` 友军出场 | Data 号、隐藏、X、Y、方向、等级、兵种级别、AI 方针、目标 Data 号、目标 X、目标 Y | 与敌军参数基本一致；**没有援军字段**。 |
| `0x47` 敌军出场 | Data 号、援军、隐藏、X、Y、方向、等级、兵种级别、AI 方针、目标 Data 号、目标 X、目标 Y | 在友军字段前增加援军标记。 |
| `0x4B` 我军出场 | 部署槽号、X、Y、方向、隐藏 | 比 AI 控制单位简单；槽号是持久化序号，不是 Data 号。 |

字段以 `BattleFieldSpec` 为准：0x46 每页 20 行、每行 11 字段；0x47 每页 80 行、每行 12 字段；0x4B 每条 5 字段。已解码的字段才开放编辑，未知值仍留在原始字段中，不因显示、切换模式或打开参数面板而重写。

### 0x46 / 0x47 字段说明

- **武将 / Data 号**：可以在角色列表中改选；重解析对应 S 形象。Data 号只用于身份、形象和既有重复限制，不是战场编号。
- **援军**：仅 0x47 可编辑；0x46 不显示此项。普罗对话框提供援军勾选框，但现有静态写出记录显示其 0x47 援军值来自固定初始化路径。不能照搬这条可能丢失用户勾选的写出行为；cczEditor 以剧本字段为准，并对照样本回读确认。
- **隐藏、坐标、方向**：对应 0x26、0x04/0x04、0x2B 字段；方向保留引擎原始 0–3/默认哨兵映射，UI 标签沿用现有 `朝北/朝东/朝南/朝西/默认方向` 转换，不把视觉帧方向写回原始 EEX。
- **等级**：沿用原编辑器 `set_level` 生成的正/负等级偏移选项与默认哨兵。缓存值不是绝对人物等级；不能用显示值直接覆盖成绝对等级。
- **兵种级别**：沿用 `Dialog_70` 当前下拉框枚举索引。它属于出场记录字段，不是 `Data.e5 +26` 的兵种移动力类别，也不是 S 形象 `arm_kind`。现阶段只保证保存枚举原值；不重新解释它的游戏语义。
- **AI 方针**：沿用编辑器配置的策略枚举：被动出击、主动出击、坚守原地、攻击武将、到指定点、跟随武将、逃到指定点。当前代码依方针 3/5 显示目标武将，依方针 4/6 显示目标坐标；其它策略隐藏目标控件，但保留未激活目标字段原值。
- **目标**：目标武将字段通过 Data 号映射；目标坐标字段单独编辑。选择“攻击武将/跟随武将”显示武将选择；选择“到指定点/逃到指定点”显示 X/Y。写入目标时三字段应作为一个原子值处理，避免半条目标记录。

### 0x4B 字段说明

- **部署槽号**只显示为槽位/战场编号；已有写回计划会在增删时压紧/续号。参数窗不可把它作为 Data 号编辑。
- 可持久化编辑项为 X/Y、方向、隐藏。
- 新增单位在当前编辑会话内可以带所选 Data 号来预览形象，但 EEX 的 0x4B 不存该身份；从剧本读入的旧 0x4B 也无法还原 Data 号。UI 应对旧记录显示中性槽位标记；不能宣称换形象能保存到剧本。新单位会话内形象是否允许临时替换，可在 UI 审阅时决定，默认不纳入第一阶段。

## 交互方案

参数编辑分成两条入口：工具栏的“默认参数”按钮打开非模态默认参数面板；地图上的右键菜单提供当前单位单体编辑或当前多选组批量编辑。角色与坐标等身份字段不进入批量编辑。参数控件分成两部分：

1. **新增默认值**：只编辑当前部署类别为 0x46/0x47 时今后新增单位的默认参数；0x47额外显示援军。0x4B 我军出场不使用此默认参数入口。
2. **当前单位与多选组**：右键单个单位打开其支持字段，修改一次作为一个撤回事务；右键多选组内单位打开批量参数面板，把面板中的共同参数统一应用到整组。批量面板不提供 Data 号、坐标或临时形象。0x46/0x47 的单体编辑可改 Data 号；0x4B 槽号只读。地图选择、控件编辑和预览叠加共用当前活动条件分支。

批量编辑启动时，先比较选中单位之间的原有参数值。仅当组内原值不统一时显示预警，并列出不同参数；组内原值统一、只是准备改成另一个值时不预警。批量面板不编辑的身份与坐标字段不纳入批量赋值；若整组已有目标值，应用时不为该字段生成无意义的 dirty 标记。

### 地图参数预览

- 地图仍是全场预览的主视图。仿照参考图，在现有状态栏下方的紧凑控制行/右侧控件区只放一个“预览切换”按钮，遵循当前侧栏显隐布局。按钮打开可选参数菜单；菜单项为“战场编号、等级、兵种级别、行动方针、援军、无”。朝向不提供地图叠加标签，因为直接从单位形象即可辨认。隐藏性沿用现有半透明效果，不进入该菜单，也不增加隐藏标签。点击某项才切换预览；菜单内当前项带勾选。切换为“无”时清除可选参数叠加。阵营不占用菜单标签，改由下述常驻描边表达。
- 阵营描边始终显示，不随“预览切换”模式关闭：在单位占据的逻辑格内侧画细边框。我军 `0x4B` 使用状态栏已有红色 `Gdiplus::Color(255, 255, 80, 80)`，敌军 `0x47` 使用蓝色 `Gdiplus::Color(255, 100, 165, 255)`，友军 `0x46` 使用橙色 `Gdiplus::Color(255, 255, 165, 55)`；颜色直接复用 `BattlePreviewPage.cpp` 的状态栏阵营色，不另建一套映射。按逻辑格描边，不描人物贴图轮廓，以免透明像素、头像/兵种图差异和缩放影响可读性。已有选中单位/分组高亮保留在描边之外，避免颜色互相覆盖；隐藏单位仍按原逻辑半透明，描边继续可见。同格出现多个阵营时，将内框按阵营分段着色，不把整格误标为某一个阵营。
- 鼠标从按钮移入下拉菜单时菜单保持打开；离开按钮和菜单区域后收起，按 Esc 也可收起。菜单尽量锚定在控制区并保持在窗口可见范围内，不因打开菜单重建右侧单位/笔刷列表；切换模式只请求地图画布重绘。
- 单位悬浮参数卡独立于地图参数层选择；选择“无”只清除全场参数徽标/目标线，常驻阵营描边和鼠标指向单位时的头像参数卡仍保留。
- **行动方针模式是首个重点**：在每个可解码的友军/敌军单位上显示短标签：`被`（被动出击）、`主`（主动出击）、`坚`（坚守原地）、`攻`（攻击武将）、`到`（到指定点）、`跟`（跟随武将）、`逃`（逃到指定点）。未解码或越界值显示 `?`，不猜测成合法策略。0x4B 我军没有 AI 方针字段，不显示方针标签。
- 对方针 4/6 的坐标目标，在目标格绘制目标标记并用细线连接来源单位；坐标无效或超出地图时只在选中单位摘要显示原值，不画虚假的目标格。对方针 3/5 的 Data 号目标，仅当当前活动分支中恰好解析到一个目标单位时绘制目标环和连接线；若目标缺失或因复制人模式而不唯一，则显示 Data 号/“目标不唯一”，不擅自指向某个同号单位。目标线先于单位标签绘制，标签保持清楚可读。
- 其它参数层以单位为锚点显示紧凑徽标：战场编号只显示战场编号；等级显示原有等级偏移格式；兵种级别显示原枚举标签；援军显示“援”标记。朝向不叠加标签，直接从单位形象辨认。阵营仅由常驻格子描边表达，不重复绘制阵营标签。隐藏单位继续使用现有半透明效果，无论当前显示哪种参数层都保持一致，不再额外绘制隐藏标签。4B 只显示可持久化的槽号/战场编号，不虚构 Data 号；不适用字段不绘制徽标。
- **单位悬浮参数卡**：鼠标移到有且仅有一个单位的格子时，自动显示一张地图内浮卡；卡片含头像和该单位所有适用且已解码的参数。鼠标移到另一单位格时原位更新内容与头像；移到空格或画布外立即隐藏，不保留上一单位信息。悬浮卡由战场画布自身绘制，不创建会抢鼠标焦点或截断 MouseMove 的独立提示窗口。
- 悬浮卡采用“左侧头像、右侧身份与参数”的紧凑布局，靠近悬停单位但不压住鼠标指针；临近画布边缘时翻转到另一侧并限制在画布可视范围内，不盖住顶部状态栏、控制行或右侧面板。0x46/0x47 显示 Data 号、角色名、战场编号、阵营、坐标、隐藏、等级、兵种级别、AI 方针与对应目标；0x47 额外显示援军。朝向由单位形象表达，不在悬浮卡重复显示。0x4B 只显示槽号/战场编号、坐标和隐藏；仅当本次会话确有临时 Data 身份时才显示相应头像/名字。
- 头像复用 R 预览的 `resolve_portrait` 与 Data.e5/Face.e5 资源解析，普通战场头像使用标准表情状态。头像资源和 Face.e5 解析结果按 Mod 资源根目录/修订版本共享缓存，不随剧本切换重复读档或解析；已解码头像按 Data 号与头像状态缓存，鼠标在同一单位上移动不重复解码。头像资源缺失或解析失败时保留参数卡并显示中性占位图。0x4B 旧记录没有 Data 号时显示中性占位图和“身份未知”；不得用战场编号或部署槽号代替 Data 号查询头像。
- 若同一格命中多个单位，悬浮卡显示“此格有多个单位，无法唯一预览”提示，不任意挑选其中一人。地图上方状态区继续显示坐标、地形、阵营、战场编号和角色身份；单击选中后的“当前单位”控件仍可编辑该指令字段，悬浮卡只读。
- 预览层读取当前 `BattleEditorState` 的实时值；新增、调整、撤回、写回重基线和条件分支切换后随画布刷新。只改变显示状态，不改单位字段、不产生 dirty 标记或撤回事务。该状态按每个 S 文档会话保存，剧本切换后恢复各自的显示模式。
- 地图无有效网格投影时禁用地图预览模式并说明原因。所有徽标、目标线和悬浮卡受画布裁剪，缩放、拖图和右侧面板显隐不触发列表重建；绘制仅遍历当前活动分支内可显示单位。目标 Data 号使用一次性索引表解析，避免单位两两比较。平移期间隐藏悬浮卡，平移结束后按鼠标当前落点重新命中并显示，防止卡片指向旧格子。

## 状态存储与编辑规则

- 默认参数存入当前 S 文档、当前条件分支、当前部署类型对应的参数 profile；不能放进共享静态缓存。切换剧本恢复该剧本，切换条件分支恢复该分支。
- 角色选择只更新 Data 号与会话形象，不覆盖用户已编辑的默认参数。参数面板提供显式“恢复默认参数”动作；每个字段区分原始默认、用户覆盖值。
- 默认 profile 只影响之后新增的单位，不回头改动已上场单位。
- 已上场单位更新复用 `BattleUnitPatch` / `ApplyPatch`，通过 `dirty_fields` 精确记录变更；批量窗口只处理组内共同且可编辑的参数。目标 Data 号只在方针 3/5 时写入，目标坐标只在方针 4/6 时写入，其余不适用字段保持原值。字段对原始记录不存在时拒绝修改而不是扩写结构。
- 多选状态下再次单击未选单位会加入分组，单击已选单位会将其移出；拖动继续沿途选取单位；双击空格清空整组。批量参数修改复用同一字段 patch，以一个撤回事务应用于整组；身份、坐标和临时形象保持单体操作。
- 快速模式固定 Scene1；条件树模式只显示当前可达布置。参数操作与地图预览的作用域均与画布当前 `BattleEditorState` 一致，不改不可达分支或其他 Section。

## 实施阶段与验收

1. **字段规范与测试**：覆盖三种字段角色、方向/等级哨兵、策略条件字段、原始未知值不变，以及批量参数事务与组内原值差异预警。
2. **新增默认值**：在每个分支工作区保存敌/友类别 profile；选角不重置手动默认值；新增 0x46/0x47/0x4B 分别生成预期字段，默认 profile 只应用于 0x46/0x47；撤回恢复 profile 与单位缓存。
3. **既有单位参数**：实现分类字段表与单体/批量控件；测试字段 dirty 标记、单事务撤回、组内参数统一、差异预警语义、0x46 无援军项、0x47 援军项、0x4B 槽号只读。
4. **地图参数与悬浮预览**：验证我军/敌军/友军格子描边分别复用状态栏红/蓝/橙色，且在“无”模式、隐藏单位、缩放和平移时保持正确；同格多阵营使用分段描边，选中/分组高亮仍清晰可辨。验证战场编号/等级/兵种级别/方针/援军徽标、方针目标关系、隐藏单位持续半透明且无朝向重复标签；测试头像解析、同格单位切换、空格立即隐藏、4B 身份缺失占位、多单位重叠提示、边缘翻转与平移恢复。切换预览模式或悬浮卡不得改变单位或写回状态。
5. **往返验收**：在隔离副本测试三类指令参数变化、原生保存重开、再次解析一致；确认 0x4B 旧记录不虚构 Data 号，0x47 援军不是静态写成常量。
6. **后续扩展**：未来如需支持更丰富的批量属性刷，再单独评估 Pu Luo `mouse_painter` 的刷写模式；不改变当前单体/批量编辑语义。

## 待确认的实现细节

- 当前资源内“兵种级别”下拉项的确切显示名需要在本机 UI/字符串资源中核实；第一阶段只沿用原枚举值。
- 普罗 `Assembly-CSharp.dll` 的援军字段写出是固定初始化，和其对话框勾选框不完全吻合；需要以用户副本做一次保存/重开对照，才能决定它是工具缺陷还是字段有其它写入路径。
- 旧 0x4B 记录没有可持久化的角色身份；地图战场编号层只显示槽号/战场编号，不虚构 Data 号。阵营不使用单独地图标签，而用常驻的逻辑格描边表示。
