# S 战场统一布置笔刷与来源感知写回设计

## 状态与替代关系

本设计根据用户于 2026-09-24 确认的方案整理。它扩展 S 战场预览中的角色列表与“小兵笔刷”，并替代 `2026-09-23-s-battle-role-list-and-minion-brush-design.md` 中“仅临时放置、依赖既有来源槽、不得写回 EEX”的边界。旧文件保留原状，作为历史设计记录；实现以本设计为准。

**2026-09-25 证据修订：**本设计中 0x4B 的角色身份假设被静态证据推翻。cczEditor 将字段 0 标注为“编号”，S_10 样本值为 0..11；普罗 kind 0 导出时也写递增槽号而非 `Piece.data_id`。因此，0x4B 字段 0 不能作为角色 Data ID。预览现按此边界区分：新放置时只在当前会话显示选中的 S 形象，导入槽显示编号标记。纯值计划与原生事务可以继续验证，但产品写回仍须等待外部导出接受性及原生保存重载证据。详见 `workspace/REVERSE-普罗工具战场布置器.md` 的 2026-09-25 修正记录。

本设计只覆盖 S 战场单位布置、暂存、增量写回和撤回，不扩展 R 场景，也不实现方针、隐藏性、等级、目标等属性编辑。

## 目标

在独立的 S 战场页提供一个统一的单位布置流程：用户选择单位身份、设置当前布置笔刷的出场类别与朝向，在地图上以正确 S 形象预览并放置；所有新增和既有单位变化先进入统一缓存，最后通过一次可撤回的原生文档事务增量写回对应的 EEX 指令。

该流程不得要求目标 Section 预先存在 0x4B、0x46 或 0x47 指令，也不得以删除全部旧指令再整体重建作为常规提交方式。

## 非目标与隔离边界

- S 战场使用自己的地图坐标、单位目录、S 形象缓存、布置状态与撤回状态。
- 不读取 R 角色表，不调用 R 预览 session、R 的位置来源结构或 R 的 Undo 栈。
- R“调整位置”只作为交互与写回原则参考：追踪数据来源、校验来源、只更新发生变化的字段、以单个事务提交。S 的来源定位必须支持“一条指令内多条单位记录”。
- 本阶段只开放我军/友军/敌军类别与朝向。其他参数继续采用对应指令的明确默认值；缓存模型必须允许后续增加属性而不改变主缓存和布置流程。
- 不修改普罗工具或游戏引擎。

## 界面与布置交互

### 身份来源与布置笔刷职责

- 右侧 S 专属侧栏保留“角色列表”和“小兵笔刷”，并提供隐藏/恢复入口；隐藏侧栏不得重置地图视口、筛选或列表状态。
- 角色列表和小兵笔刷只决定“放置哪个 Data 号”。角色列表用于单个角色；小兵笔刷用于连续 Data 号组，并按已确认的分组规则选择组内下一个可用号。
- 唯一的通用“布置笔刷”决定“以什么出场类别及朝向放置”。出场类别是笔刷属性，不是我军、友军、敌军三套独立入口。类别与朝向在每次放置时快照到该单位，后续切换笔刷不改变已缓存单位。
- 选中既有单位后，只有显式执行“将当前类别应用到选中单位”才会改变该单位类别并在写回时迁移其记录；单纯切换布置笔刷类别只影响之后的新放置。
- 当前类别映射：我军生成 0x4B，友军生成 0x46，敌军生成 0x47。不得由来源指令是否存在决定能否选择类别或放置。

### 半透明 S 形象与朝向

- 选择列表项后进入待放置状态。悬浮预览随鼠标定位到当前有效地图格，以半透明方式绘制该单位的 S 战场形象。
- 悬浮形象复用现有 S `BattleAssetCache` 与 S 形象解析/绘制路径，按当前 Data 号和兵种解析；不得回退到 R 角色表或仅用文字占位来代替已可解析的 S 形象。
- 待放置状态下，鼠标滚轮按 S 战场真实方向定义逐档改变当前布置笔刷朝向，并立即更新半透明预览。方向数值及循环次序须由 S 指令字段和普罗/编辑器源码确认，禁止凭 R 方向枚举推断。
- 单位放置后成为正常不透明的缓存单位；之后滚轮改向只影响当前笔刷及之后的放置，不回写或旋转已放置单位。
- 角色列表的单人放置成功后结束该单人待放置状态。小兵笔刷放置成功后推进到组内下一个可用 Data 号并继续待放置；左键按住时可在每个新进入的有效逻辑格连续盖章，同一格不重复放置。非法位置或失败不消耗 Data 号。
- 右键命中单位时打开“单位操作”子菜单，现阶段包含“调整位置”和“删除”。删除只改变缓存；不再执行右键立即删除。未来可另行设计批量删除，本阶段不实现。
- 通过右键子菜单的“调整位置”进入调整模式；半透明单位跟随鼠标，点击目标格只修改缓存坐标并结束本次调整。调整模式参考 R 的跟随预览/单击落位交互，但不复用 R 的角色状态或坐标写回代码。

### “调整位置”的身份与生命周期规则

位置调整以稳定的 `cache_id` 选择单位，不以坐标、Data 号、TreeView 行号或当前笔刷类别作为对象身份。`cache_id` 在一次 S 布置会话内单调分配；位置改变、删除其他单位、0x46/0x47 记录紧凑化均不得改变它。重载文档会开启新会话并重新分配。

每个单位同时区分三种信息，禁止互相代替：

1. **来源锚点**：仅表示它是否已经存在于当前 Section 的 EEX 中。既有单位锚点包含 `logical_key + instruction_id + row_index + source_group/page + original_fields`；重复的 0x46/0x47 指令必须精确到指令节点和记录行。`original_fields` 是导入时基线，后续缓存编辑不得覆盖。
2. **部署类别**：单位最终应写入 0x4B、0x46 或 0x47。对既有单位初始等于其来源指令；新单位在落笔时复制当前统一笔刷类别。0x47 的 `reinforcement` 是字段参数，不是敌我阵营标记。切换笔刷类别只影响新落笔，不会暗中改动已选中单位类别。
3. **缓存状态**：既有单位可为未改、坐标已改、待删除；新单位为待写入。当前阶段的“调整位置”只更新 `cache_id` 对应记录的坐标，并把 X/Y 标记为脏字段；新单位只改变暂存坐标。两类单位都不在鼠标移动或点击落位时写入 TreeView。

操作流程：右击命中唯一单位后提供“调整位置 / 删除”。选择“调整位置”锁定该 `cache_id`，原位置保留为暂存基线，半透明 S 形象跟随鼠标；左键落在有效且未占用的格子时，仅更新缓存坐标，取消则保持原状态。若目标格有多个单位或来源锚点已经失效，拒绝该次操作，不猜测对象或行号。角色类别、来源指令与其它行不因移动改变。再次调整只覆盖该单位的最终暂存坐标，不叠加写入多条命令。

既有单位在写回前必须以完整来源锚点重验节点类别、记录行和整行原始字段基线；任一字段已被外部编辑改动就拒绝整个事务。新单位不要求已有来源锚点，写回时按其独立的部署类别分组落到已证明的可用槽或新建指令。写回成功后才给新单位绑定真实 EEX 来源锚点，并把它重基线为未改；撤回该次文档写回时恢复原节点并撤销这些新锚点，但保留用户缓存里的最终布阵作为未写回状态，供重试。

## 统一缓存数据模型

缓存是规范化的单位集合，不以指令类型、TreeView 节点或列表页作为主身份。每个单位记录至少包含：

- 会话内稳定且单调分配的 `cache_id`；
- Data ID、S 地图格坐标、**部署类别**（0x4B/0x46/0x47）与朝向；
- 版本化、可扩展的属性子结构，用于未来添加隐藏、方针、等级、目标等字段；
- 可选、不可变的来源锚点：原指令逻辑键、原指令号、源记录行、源分组和导入时原始字段基线；
- 新增待写、既有未改、既有字段已改、既有待删除等暂存状态。

来源锚点表示“现有 EEX 里这条记录在哪里”；部署类别表示“新状态最终属于哪种出场命令”。二者不得复用同一字段。新放置单位没有来源锚点仍是合法缓存记录，但必须有部署类别。新旧单位统一参与地图呈现、按 `cache_id` 选择、移动、删除和写回规划。0x47 `reinforcement` 单独保存在可扩展属性字段中，不用于推导部署类别。

导入既有记录时保留原始字段及未识别字段。序列化只覆盖明确标记为修改的语义字段；若单位改换部署类别而目标指令格式无法承载原有字段，提交必须报告不可无损迁移并拒绝静默丢字段。

小兵笔刷分配遵守已确认的身份规则：每次重新选择小兵笔刷开启独立缓存批次；批次起始号是本批实际分配的首个 Data ID，不是笔刷组范围下界（范围前部可能已被既有单位占用）。删除只压紧同一批次内幸存单位，并保持该批次实际起始号稳定；不得留下 `358、360` 这样的跳号，也不得整体漂移为 `359、360`。不同批次即使来自同一笔刷也不得相互重编号。从剧本导入的既有单位 Data ID 不因编辑其他批次而重编号。Data ID 与指令记录序号始终是不同概念。

## 会话与来源感知增量写回

### 开始编辑与暂存

1. 以当前 S Section 为作用域解析地图及其中已有的 0x4B/0x46/0x47 单位，转换为统一缓存；其他 Section 的记录不混入。
2. 目标类别指令可以为零条。用户仍可通过通用笔刷放置新单位。
3. 地图上的添加、删除及本阶段支持的单位位置变化均先改缓存。缓存变更不修改 TreeView、EEX 文档、dirty 标志或磁盘。
4. 缓存有未提交变更时显示未写回状态；切换文档、刷新或重新载入前应明确提示丢弃未提交变更，避免静默丢失。

### 写回规划

用户点击一次“写回”后，先从统一缓存生成完整变更集，再执行校验；不在鼠标每次落笔时写剧本。变更集包含既有记录字段更新、记录新增、记录删除、类别迁移及必要的新指令节点。

- 既有单位通过“缓存 ID → 来源锚点（指令逻辑键 + 指令号 + 源记录序号/分组）”定位；提交前确认节点仍存在、指令号正确、记录行布局完整且整行值与不可变来源基线一致，避免因节点重排或陈旧快照写错行。Data ID 和 TreeView ordinal 都不是缓存身份。
- 只调整既有单位位置时，像 R 的调整位置一样仅更新来源行中明确的坐标字段；本阶段滚轮转向只作用于待放置笔刷，不旋转已存在的单位。隐藏、方针等未修改字段保留原值。
- 新增单位按缓存中的部署类别分组；优先填入目标类别既有指令中经验证的可用记录槽；没有可用槽或目标类别无指令时，按 S 原生字段格式创建新的同类指令。新增不需要伪造或预先创建来源指令。0x4B 已确认每条独立保存一个单位槽；0x46/0x47 使用固定容量记录页。普罗最终分组/插入顺序仍需样本保存重载闭合。
- 0x4B 按其单单位指令格式新增/删除；字段 0 是 `DeploymentIndex`，不含持久化角色 Data ID。当前值计划在新增/删除造成布局变化时按来源 ordinal 压紧存量槽号，并按缓存顺序为新增项续号；坐标单改不重排规范序号。0x46/0x47 按多单位记录格式增删/更新记录。所有这些仍须通过真实样本保存重载验证后才可开放写入。
- 删除既有单位只移除该单位记录；不得因删除一个单位删除含有其他单位的整条 0x46/0x47 指令。若删除后其来源指令为空，是否保留空节点或删除节点按原生编辑器和普罗的序列化规则确定。
- 改变既有单位的部署类别时，从原类别记录移除并在目标类别建立记录；若目标格式会丢失无法映射的已存参数，必须阻止提交并给出字段级原因。
- 既有非部署指令及其相对次序、未编辑单位的原始参数保持不变。新增同类指令的插入位置和各类别最终输出次序必须依普罗工具的真实序列化逻辑确定，不自行假设。

### 原生事务、撤回与保存

- 先完整构造并校验变更集，再开启一次原生编辑器文档事务。任何来源校验、编码、节点创建或更新失败都回滚全部操作，且不得留下半写入或将文档标脏。
- 成功后只建立一个“战场布置写回”撤回项，能一次撤销本次全部记录和节点变化；撤回恢复写回前的相关指令字段、节点、文档 dirty 状态及树选择。
- 写回操作将规范化指令更新到当前编辑器文档；磁盘 EEX 持久化仍通过编辑器原有保存流程完成，不直接覆盖源文件。
- 完成写回后使用正常预览刷新路径重新解析 S 缓存，确认地图显示与新文档树一致。

## 错误处理与安全边界

- 地图/地形或坐标证据不完整、Data ID/形象无法解析、位置非法、来源节点冲突、记录字段不完整、容量超限、类别迁移不能无损编码、原生节点 API 失败时均拒绝提交，并保留暂存缓存供用户修正。
- 拒绝原因应区分预览放置失败、写回计划校验失败和原生事务失败；不得再用“未闭合”之类泛化诊断阻止用户操作而不解释具体缺项。
- 任何产品写回入口只有在字段格式、普罗类别/顺序、原生 TreeView 写入与保存回读路径有直接证据后才开放。合成单元测试只能验证转换逻辑，不能替代原生文档回读。

## 验收标准

1. R 文档、R 角色表、R 预览状态和 R 撤回行为不受 S 布置功能影响；S 页只使用 S 数据、形象和坐标。
2. 角色列表单人和小兵笔刷均能显示正确半透明 S 形象；预览格坐标与最终缓存落位一致。
3. 滚轮每档按已证实的 S 方向序列改变待放置预览；落位记录正确朝向；后续转向不修改已放单位。
4. 我军/友军/敌军通过同一布置笔刷切换，分别进入同一缓存并映射至正确 0x4B/0x46/0x47 输出；目标 Section 完全没有对应出场指令时仍可新增。
5. 小兵笔刷按住左键跨新格连续落位、非法格不消耗身份号、删除后按稳定起始号紧凑分配、撤回后身份分配与地图状态一致。右键命中单位打开含“调整位置”“删除”的子菜单，右键本身不直接删除。
6. 已有指令的单个单位调整位置只修改目标记录的坐标字段；类别显式迁移只改部署类型及目标类型必需字段；同指令其他单位、未知字段、其他剧本指令不变。滚轮改变待放置朝向不修改已放单位。
7. 新增、删除、改派类别的变更集覆盖：无来源新单位、类别指令不存在、现有记录有空槽、记录容量已满、既有来源失效、类别迁移目标格式字段不足。
8. 一次“写回”生成一个文档事务和一个撤回项；人为注入任一步骤失败后文档、树节点、dirty 状态与缓存基线均无半提交结果。
9. 对副本完成 EEX 保存、关闭重载、S 预览重解析的往返测试；比较预期单位类别、Data ID、坐标、朝向及未修改字段。真实窗口交互仍由用户实测验收。

## 实现前必须闭合的证据项

1. 从普罗 `Assembly-CSharp.dll` 中定位布置笔刷到最终序列化的完整调用链，确认 0x4B/0x46/0x47 的字段布局、输出顺序、记录分组、空槽处理、Data ID 分配/压缩语义。
2. 从 cczEditor 原生源码确认 TreeView 节点创建、`int_data` 长度/字段类型、更新显示、删除节点及文档撤回/dirty 管理的实际接口；不得直接调用 R 的 `PositionSource`。
3. 用至少一个无 0x4B/0x46/0x47 节点的 S Section 和一个包含多条 0x46/0x47 指令的副本，覆盖全新增、既有记录更新、删除、混合新增与删除、类别迁移；验证正常保存并重新加载。
4. 保留逐层测试：规则/序列化单测、原生节点桥接测试、文档事务/撤回测试、Release Win32 构建、真实窗口回读。任一证据未通过时，不显示写回成功或保存成功。

## 2026-09-25 语义修正与待确认决定
