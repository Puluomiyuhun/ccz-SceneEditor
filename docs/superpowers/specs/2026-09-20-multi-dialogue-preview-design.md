# 14号单指令多对白预览设计

## 目标

让 0x14“对话”指令支持在同一条文本中连续写入多个 `&说话人` 段落，并在动态预览中按对白段分别显示、播放、步进和步退。剧本树与写回格式保持不变；本功能只扩展内置 EXE 的预览时间线。

## 明确范围

- 只处理 0x14“对话”。0x15、0x16、0x7A 以及其他文字指令保持现状。
- 先执行现有文本标准化：转义 `\\n`、CRLF 统一为换行。
- 仅当 `&` 位于文本开头或换行之后时，才作为新对白标记。
- 标记行格式为 `&说话人`，说话人以该行结束为边界；正文持续到下一个合法标记或文本结尾。
- 普通正文换行仍属于当前对白，不会单独生成播放事件。
- `&*.174` 等现有说话人/头像标记继续复用既有解析器。
- 标记缺少换行分隔符、说话人为空或无法形成有效段落时，回退到原单对白解码，并保留诊断，不静默丢文本。

## 核心方案

采用“播放时间线虚拟事件”方案，而不是拆分 `ExecutionNode`：

1. 在对白模型中提供 0x14 专用的多段解码结果；原有单段 `DialogueState` 接口继续保留，单段输入的结果不变。
2. 播放时间线构建时，将一个 0x14 节点展开为若干 `PlaybackEvent`，每个事件携带父节点键、对白段序号和总段数。
3. 场景回放仍按父节点执行一次；动态预览仅用虚拟事件选择当前对白覆盖层，避免重复执行同一节点的场景副作用。
4. 时间线以展开后的事件数组计算范围、进度、播放、步进和步退。

## 数据与接口

`DialogueSegment` 至少包含：说话人、正文、已解析的人物引用、段序号、总段数和诊断信息。

`PlaybackEvent` 增加对白段元数据；保留现有 `LogicalNodeKey` 和 `RuntimeNodeHandle`，不修改剧本节点身份。时间线增加选定节点的对白段起点/终点概念：

- `target_begin`：选定节点第一段对白事件。
- `target_end`：选定节点最后一段对白事件之后的半开区间位置。

普通单段节点满足 `target_end == target_begin + 1`，兼容现有调用方。

## 播放语义

- 选中多对白节点时，静态预览显示第一段。
- “自开头播放到此”范围为 `[0, target_end)`，结束在选定节点最后一段对白。
- “自此播放到结尾”范围为 `[target_begin, events.size())`，从选定节点第一段对白开始。
- 步进/步退把每个对白段当作一个独立播放单位；普通节点仍为一个单位。
- 进度条总数、当前序号和播放终点均按虚拟事件计算。
- 后续实际节点到来前，当前对白段继续保留；场景状态沿用已有动态回放逻辑。

## 兼容与错误处理

- 单段 0x14、无 `&` 文本和所有非 0x14 指令保持原行为。
- 不改换行辅助开关、字节上限、保存格式或写回逻辑；二者只共享文本标准化步骤。
- 动态帧构建从“仅按 LogicalNodeKey”扩展为“父节点键 + 段序号”，但父节点场景只回放一次。
- malformed 标记回退旧逻辑并给出诊断，不能产生空事件或吞掉正文。

## 验收标准

- 双段、多段 0x14 文本按顺序产生对应对白和头像。
- `&*.174` 等头像引用继续正确解析。
- 普通正文换行、换行辅助插入的换行不会误拆对白。
- 动态播放、步进、步退、两种播放范围边界均以对白段为单位正确工作。
- 单段对白、普通 Scene、出战界面、自由 R、条件树和写回功能回归通过。
- 全部测试在不依赖外置 DLL 的内置 EXE 代码路径上执行。
