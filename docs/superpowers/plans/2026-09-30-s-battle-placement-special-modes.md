# S 战场复制人、地形无限制与兵种地形控制实施计划

## 已批准范围

- 复制人模式默认关闭；开启后只绕过 Data 号重复限制。笔刷新批次可以复用已用 Data 号，单批次内仍按连续 Data 号分配，以满足现有写回规划器约束。
- 无地形限制模式默认关闭；开启后只绕过兵种地形 `0xFF` 检查，不绕过地图边界、目标格占用、人数上限或笔刷批次连续性。
- 地形控制使用当前 Mod 的 `Data.e5` 资源 4（40×60），按 Data 号对应的 `Data.e5 +26` 兵种码映射至 40 行，再查地形号对应的第二段 30 列。仅拒绝 `0xFF`；不计算特技、装备、行动力预算或运行时兵种变化。
- 覆盖角色列表放置、小兵笔刷、单体位置调整、多选组位置调整。左侧指令树手工编辑和现有出场指令格式不变。
- 新放置的 0x4B 角色在序列化前仍有 Data 号，可在放置阶段使用对应兵种码；已载入且缺少 Data 号的 0x4B 单位，在受限模式下位置调整时失败关闭并说明原因。
- 两个模式按打开的剧本文档保存、互相独立、不进入撤回栈，不写入 EEX；切换条件树分支时继续保持。

## 实施步骤

1. 增加带边界校验的 E5 资源视图解析器，并把 Hexzmap 解码改为复用它，保持原有地图限制。
2. 新增移动地形矩阵类型和资源 4 解析；在角色目录中显式暴露 Data.e5 `+26` 兵种码，并将矩阵作为 S 预览的 Mod 资源预载，按规范化 Mod 根目录与 `Data.e5` 修订号缓存一份共享对象。
3. 每个 S 文档编辑状态只持有共享矩阵的只读引用，不复制矩阵；集中实现按 Data 号查兵种并判断目标格的 terrain gate，覆盖新增、笔刷和单/组移动。Mod 切换时保留旧会话正在引用的缓存版本，`Data.e5` 修订变化后加载新版本。
4. 增加两个独立的 session-local UI 开关；同步条件分支工作区，保证撤回不改变开关。
5. 用核心矩阵解析测试和 BattleEditorOps 行为测试覆盖行映射边界、`0xFF`、缺失元数据、模式隔离、重复角色、笔刷连续性、边界/占用/人数保护及未知 0x4B 移动。
6. 编译调试/发布 Win32 测试和编辑器，运行 Battle 聚焦回归与全量核心测试；更新兵种地形知识页和当日工作记录。

## 验收条件

- 默认状态拒绝重复 Data 号和该兵种不可进入的地形；开启对应单一模式后，只解除对应的一种限制。
- 不同 Data 号/兵种在同一地形上可得出不同结果。
- 无效兵种码、缺失 Data 号、缺失/截断矩阵不会被当成可通行；地形无限制模式仍保留地图边界、占用、人数和批次约束。
- 资源来自当前 Mod 的 `Data.e5`；跨剧本切换不复用其他 Mod 的矩阵。
- 不改变三类出场指令的数据布局、既有指令树编辑逻辑或写回流程。
