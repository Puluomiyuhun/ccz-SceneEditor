# S 战场动态写回与无现存指令插入方案

## 目标

按用户已批准的范围完成两项修正：

1. Scene1/Section 内容在编辑器中动态变化时，不再因修订号变化一概冻结写回；保留文档身份、固定 Section、树代次、条件可达范围、节点映射和提交期间并发变更等安全校验。对同一来源字段的并发修改执行三方协调：预览未改的字段保留剧本当前值；预览修改且剧本未改的字段写入预览值；双方改成相同值可接受；同一字段改成不同值时给出明确冲突诊断。来源被删除、类别改变或无法唯一映射时仍拒绝。
2. 当前作用域没有可用的 `0x46/0x47/0x4B` 出场指令时，新增指令锚定到用户当时选中的普通指令之后（若该指令有子树，则仍作为其整个子树之后的同级指令）。拒绝 Scene/Section、结构标记和事件结束节点作为选择锚点。首次新增 `0x4B` 时，用原生 `0x02`“内部信息”节点建立“我军出场”分组，并将本批新增的我军指令放入该分组。

## 约束与已确认事实

- 写回事务必须仍然原子；撤回需要完整移除新增分组及其子节点。
- 已有 TreeView `CreateZsj(2, ...)` 的原生结构是同级 `0x01` 标记、`0x02` 信息节点，以及 `0x02` 下以 `0x00` 结束的子事件。应复用这一原生结构并通过现有 `long_char_data` 存储分组文字，不手拼剧本字节。
- 当前捕获的 `selected_path` 是 Section 内的树路径；快速模式完整文档捕获目前不保留它，需把当前 TreeView 选择句柄带入完整快照，再在固定 Scene1 Section 子树中重新求路径。
- 当前的“修订号严格相等”不是唯一阻断点：快照构建还会拒绝任何出场字段/序号变化，计划构建也会要求预览基线等于当前树字段。要修的是整体差异协调链，不能只删除一条修订号比较。
- 保留写回期间 content epoch/tree generation 的前后校验。这些检查用于阻止事务执行期间的并发变更，与“编辑器内容允许正常变化”不同。
- 保留已有工作树中与本任务无关的改动和临时文件，不清理、不重置、不提交。

- 添加无现存出场指令的 selected-path 锚点测试：普通指令后、带子树指令后均正确定位；Scene/Section/结构标记/事件终止节点被拒绝；插入锚点验证支持同级中间位置且事件最后仍是 `0x00`。
- 添加首次 `0x4B` 分组纯计划/native transaction 测试：一个 `0x02`“我军出场”分组包住同批多条 `0x4B`；提交失败回滚完整；撤回完整删除分组；第二次写入仍正常。
- 更新 PowerShell 源码契约测试，移除“PinnedSection 写回必须 revision 相等”的旧断言，并保护 tree-generation/content-epoch 检查。

### 2. 实现动态协调

- `BuildBattleWritebackSectionSnapshot` 在 PinnedSection 下将 Section 修订号作为变化信号而不是拒绝条件；保持来源路径/Section 句柄/作用域身份硬校验。
- 用原生运行时句柄在基线与当前捕获间对齐来源节点；将基线逻辑键用于预览缓存寻址、当前逻辑键和当前序号用于原生写入寻址。
- 对已有单位逐字段执行三方协调；拒绝被删/重类型/无法唯一映射的缓存来源，以及与预览改动字段真正冲突的原生更改。对固定容量指令的未跟踪新占用槽保留剧本当前值，不覆盖。
- 保持 transaction 对每条原生来源的 preimage 与当前捕获严格一致，避免预检后节点再次变化。

### 3. 实现选中指令锚点与原生分组

- 捕获当前选择句柄，并在完整文档选择 Scene1 Section 后恢复 Section 内 `selected_path`。
- 仅在活动作用域没有已有可达部署来源时，解析所选普通节点及其同级后继；用后继作为 insert-before 锚点，避免插入到所选节点的子事件内部。
- 将终止指令句柄单独保留在 native batch；预检确认 insert-before 与父节点为同级，且父节点末尾仍为唯一有效的 `0x00` 终止节点。
- 为首批 `0x4B` 新增复合变更：一次创建原生 `0x01` + `0x02`（文字“我军出场”）分组及其 `0x4B` 子指令。复合插入由 native host 保证全有或全无，并让 transaction rollback/undo 能完整删除整个分组。
- 对后续 `0x4B` 插入继续使用已存在分组的有效子事件锚点，不重复建立“我军出场”分组。

### 4. 验证与记录

- 运行 CoreTests、相关 PowerShell 集成契约、编译测试目标；检查相关文件的定向 diff，确认没有覆盖用户已有改动。
- 更新本计划的结果和验证命令；只报告实际运行通过的检查。不开压缩包、不提交 Git。

## 主要风险

- 逻辑键包含树位置，普通插入可能使后续键变化；当前运行时句柄只可在同一树代次中复用，故不得跨树重建沿用句柄。
- 4B 分组创建涉及多个原生节点和序号，必须将复合组合作为单个原子操作，不能让部分组结构留在树中。
- 预览对象的 `editor_origin_fields` 与 live `int_data` 必须分开比较，防止把未改字段旧值写回并覆盖用户刚在树中做的调整。
