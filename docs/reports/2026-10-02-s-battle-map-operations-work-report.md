# 2026-10-02 S 战场移动、复活与障碍物初版工作报告

## 交付内容

本轮在 S 预览中加入三种棋盘辅助编辑操作：

- **移动至（0x32）**：右键棋盘单位，再点目标格；滚轮可暂存调整朝向，确认时将坐标和朝向一并写回。`-1` 保留为引擎默认朝向，其他合法值为 `0–3`。
- **复活至（0x55）**：右键选择棋盘基线中已安排出场的角色，再点目标格；沿用移动至的角色选择、目标格和写回流程，只生成 0x55 指令。编辑器不检测角色运行时的在场状态。
- **添加障碍物（0x58）**：初版支持类型 `0–2`（火、船、火船），在地图上暂存多个障碍后一次写回。

三种操作都以已加载的 Scene1 作为预览和编辑基线，并将新增指令写在用户当前选定的指令之后。目标格被占用时仍允许操作；实际避障由游戏引擎处理。工具启动会退出已有的放置/调位模式，文档切换时分别保存各自的操作状态和障碍草稿；刷新失败或基线变化时会保留待处理草稿并暂停写回。

右键多选组内单位执行移动或复活时，该单位作为目标锚点，整组按原有相对格位平移；预览显示每个成员各自的目标格。滚轮可用于移动至和复活至：单体按自身朝向旋转，多选以锚点方向统一整组朝向；这些方向仅保存在操作预览中，点击目标格后才和坐标一起生成一批指令。复活未经滚轮调整时保留 `-1` 朝向字段，滚轮调整后写入显式方向。超出地图范围时整组拒绝写入；不检查目标占格。

地图指令走 S 专用原生事务，保留现有序号校验、读回、撤回与预览基线重建流程。仅拒绝把地图指令插入 0x02「我军出场」专用分组；普通条件子事件和其他内部信息分组可按选定指令锚点写入。

## 复活对象来源勘误（2026-10-02）

概念与实现更正：剧本里的“出场/未出场”描述单位是否已被安排进入剧本；棋盘运行中的“在场/不在场”描述该单位当前是否在战场正常存活。不在场可以由击杀、隐藏尚未登场或剧情离场等动态过程造成。复活只作用于已安排出场的单位，是否在场由运行时决定，编辑器不模拟或检测该动态状态。

复活选择沿用移动至的棋盘角色对象和目标格交互：右键选择棋盘基线中可识别、已安排出场的角色，点击目标格后走同一目标验证和写回流程，仅在指令构造处改为 `0x55`（移动为 `0x32`）。不从全局角色目录挑选任意 Data 号，也不根据棋盘运行时状态筛选角色。知识库的光环记录展示了引擎运行时状态字段 `unit+0x0C`，但该字段不等同于剧本的出场安排，本次编辑器没有读取它。

据此合并了移动和复活的目标格处理、验证及写回分支；角色来源仍由棋盘对象绑定。隐藏标记不阻止对象身份命中，且界面不再显示“执行时需不在场”提示，避免把引擎运行时条件误作编辑器检测结果。

验证：地图操作 UI 契约、S 会话保持和写回回归脚本通过；Win32 Debug 编辑器构建通过。测试明确检查移动/复活共用目标格及写回流程，且源码没有运行时在场检测。未进行真实 MFC 鼠标操作验收。
